# 重复操作与内存检查

2026-10-20。测试使用独立临时目录、本地模型和问卷夹具，不读取教师课堂，不请求真实服务商。没有故意把主服务推到内存耗尽。

## 重复追加的实测与修复

修复前，针对同一个对象连续执行100次；修复后提高到1000次。报告、建议与来源的内容均保持相同。

| 操作 | 修复前100次后的结果 | 修复后1000次后的结果 |
| --- | --- | --- |
| 载入备课及反馈示例 | 不重复 | 不重复，20个并发反馈载入也返回同一组课堂 |
| 保存相同模板 | 101个版本 | 1个版本 |
| 保存相同报告 | 100条多余历史，撤销确认状态 | 0条多余历史，保留确认状态 |
| 保存相同建议 | 101条历史 | 保留首次保存所需的1条历史 |
| 关联同一转写 | 101个来源快照 | 1个快照 |
| 重复预览及导入同一条反馈 | 101份预览文件，反馈数量去重 | 同一状态及小时复用预览；两个实际业务状态共2份文件，反馈仍为1条 |

另外验证100次新问答结束后，运行任务表、存储队列及问卷请求队列均回到零。新问答的200条消息、100个任务检查点按历史保存，这是实际新增内容，不属于缓存泄漏。

音频页也补充了相同转写重复校正、同一报告重复确认的100次检查；内容没变时不追加版本或历史。实际编辑仍保留历史。持续分批导入达到课堂总量上限后，下一批原子拒绝，原数据不变；在总量上限内更新已有记录仍可执行。

## 内存与浏览器检查

服务端探针在 `--max-old-space-size=256` 下执行，每阶段主动垃圾回收后采样。1000轮中，示例预热后的保留堆约6.11 MB，全部相同内容操作结束约6.39 MB；新增100次问答后约7.45 MB。重复操作阶段未出现与次数对应的大量保留堆增长。RSS会受V8已分配空间影响，不能将其与保留堆等同。

Chrome实际点击“载入问卷示例”和“更新保存状态”各210次（含10次预热），分四组采集回收后堆、DOM和事件监听器数量。同一轮内课堂数、节点数及监听器数保持不变；完整指标见本机 `artifacts/repetition-browser-result.json`。

其他浏览器边界：

- 题目和选项在页面达到服务端配置上限时停止新增或复制，不等保存才拒绝。测试各连续点击100次，并检查删除后可继续增加。
- 慢网络下定时刷新只保留一个后台读取，任务进度读取也复用进行中的请求；30次手动刷新不叠加30个进度请求。后台读取15秒超时后释放。
- 连续500次搜索输入合并为一次查询，旧查询取消；切换课堂取消来源、记录及进度的旧读取。
- 反复切换失败的历史回听40次，等待音频元数据的监听器最多一个，失败与切换时释放。

## 复现

在应用目录执行：

```sh
REPETITION_CYCLES=1000 node --expose-gc --max-old-space-size=256 scripts/verify-repetition.mjs
npx playwright test e2e/repetition.spec.js
```

Node探针默认报告为 `artifacts/repetition-result.json`，可用 `REPETITION_REPORT` 修改。浏览器使用3107和3108端口的隔离夹具。报告不加入Git。开始新预览时，至多每分钟检查一次并回收超过一小时的旧预览文件。

## 结论边界

本次证明上述重复操作在已测次数内不会无意义追加，且临时队列与监听器能释放，不是无限时长或任意规模的内存保证。真实新增课堂、问答、报告和不同内容的历史仍会增长；现已补充全局业务数据额度、历史归档及恢复机制，见[数据恢复说明](data-recovery.md)；仍未完成整学期资料规模测试。物理录音、真实大课堂数据及长时间资源压力的待验收项继续保留。
