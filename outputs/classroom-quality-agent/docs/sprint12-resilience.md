# Sprint 1、2 重复操作与故障恢复检查

2026-10-20。沿用 Sprint 3 的检查方法，使用临时目录、独立 HTTP 服务、模型/语音夹具和 Chrome 模拟教师操作。没有使用正式录音或真实模型凭据。

| 范围 | 已修复的问题 | 验证方式 |
| --- | --- | --- |
| 备课任务保存 | 初次创建或继续任务时，任务文件保存失败会留下“处理中”；工作空间保存失败留下孤立任务 | 注入存储失败，检查原消息、任务文件和重新发送能力 |
| 备课提交完成 | 成果已经保存，最终进度文件保存失败却显示失败，重试可能再次提交 | 持续拒绝最终进度写入，仍从工作空间提交记录识别完成，拒绝继续已完成任务 |
| 备课任务面板 | 已完成聊天的进度对象不断留在内存；清空监视后旧请求仍等待网络 | 浏览器连续插入1000个完成状态，缓存最多保留最近任务及最近对话；清空立即中止读取，单次读取有15秒超时 |
| 写入边界 | 非对象 JSON 导致服务端异常；缺少修订号可绕过并发保护 | 对前两个 Sprint 的写入接口提交空值、数组、基本类型及非法修订号，返回4xx，原内容不变 |
| 清空与上传 | 清空等待旧任务退出时删除整个音频目录，误删此时新上传的录音，响应也回退到旧状态 | 暂停旧语音进程，清空等待期间上传新录音，放行旧进程，确认新文件和最新响应保留、旧文件回收 |
| 上传与删除 | 上传探测期间新启动分析仍可被替换录音；分析期间可通过接口删除来源 | 提交时统一检查活动任务，删除也要求先暂停或取消 |
| 复盘并发 | 相同讨论同时发送会重复调用模型 | 两个同版本请求仅接受一个，完成后释放占用 |
| 复盘慢响应 | 回复到达前保存课程会产生仅由聊天记录引起的冲突；旧回复又可能回退界面状态 | 浏览器延迟回复，期间保存课程并填写下一条问题；仅聊天记录变化时安全重试，课程冲突不覆盖、草稿保留 |
| 重复保存 | 相同课程、当前录音或当前转写的重复选择造成无效写盘、修订号增长和报告失效 | 连续100轮、每轮三类操作，内容、修订号与报告有效性不变 |
| 录音回放 | 连续点击累积元数据/定位监听器，清空后迟到回调仍播放旧音频 | 连续1000次切换最多保留一个加载等待，只播放最后一次；清空立即释放等待 |
| 音频范围 | 合法尾部范围及超出末端的请求被拒绝；空文件和读流错误未妥善处理 | 尾部、截到末端、非法范围、空文件回归；回放流随连接关闭释放 |
| 长录音进度 | 所有事件 Promise 保留至任务结束，同时向存储排队；同步回调异常被吞掉 | 夹具进程连续4000条事件，顺序保持、异步回调峰值为1；写入异常向上传递 |
| 离开保护 | 复盘区未发送问题或正在等待回复时，离开页面没有提醒 | 浏览器验证输入时触发离开保护，清空输入后解除 |
